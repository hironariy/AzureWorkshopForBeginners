# 第10回 Azure の AI関連サービスの紹介 ドラフト

## 表紙

- 講座名: Azure Workshop for Beginners
- 回: 第10回
- タイトル: Azure の AI関連サービスの紹介
- 形式: オンライン座学
- 時間: 60分 (50分レクチャー、10分QA)
- 想定日: 2026年9月3日

## この回の位置づけ

第10回は、第12回のオフサイト AI アプリ構築に向けて、Azure の AI 関連サービスと AI エージェントの基本的な設計観点を理解する回です。
第9回では、画面、API、データストア、イベント系サービスを分けて SPA 構成を読みました。
本回では、そのアプリケーション構成の上に、モデル、指示、知識、ツール、実行環境、評価、監視を組み合わせると AI アプリケーションや AI エージェントになる、という見方を作ります。

中心に扱うのは Microsoft Foundry と Microsoft Foundry Agent Service です。
Azure OpenAI、Azure AI Search、Azure Machine Learning、Foundry Tools なども紹介しますが、サービスカタログとして広げすぎず、「AI アプリを設計するときにどの役割として見るか」を優先して説明します。

Azure Landing Zone の設計領域で見ると、本回は主に「ID 管理とアクセス管理」「リソースの編成」「ネットワーク トポロジと接続」「セキュリティ」「ガバナンス」「管理」を、AI ワークロードに当てはめて扱います。
「Azure の課金とテナント」はリージョン、クォータ、コストの注意点として触れ、「プラットフォームの自動化と DevOps」は本格的な実装ではなく、評価、監視、ガードレールを運用に組み込む入口として扱います。

本回では Azure リソースは作成しません。
Azure Portal、Foundry ポータル、Copilot Studio の画面は必要に応じて参考画像として示しますが、操作手順としては扱いません。
第11回では Azure Monitor、Application Insights、Log Analytics などの監視サービスを扱うため、本回の監視は AI エージェント特有のトレース、評価、品質、安全性、トークン、待ち時間の入口に留めます。

## 受講前提

- 第2回から第6回までで、Web 3層、VM、コンテナ、Container Apps、PostgreSQL、GitHub Actions などの基本的な構成を学んでいることが望ましい。
- 第7回で、VNet、Private Endpoint、Private DNS Zone などネットワークの基本を学んでいることが望ましい。
- 第8回で、Microsoft Entra ID、Azure RBAC、Policy、Defender for Cloud、Key Vault、Cost Management などの管理系サービスの入口を学んでいることが望ましい。
- 第9回で、SPA、Static Web Apps、Functions、データストア、イベント系サービスの役割分担を学んでいることが望ましい。
- AI、機械学習、データサイエンス、プロンプトエンジニアリング、MLOps の経験は不要。
- 本回は座学のみで、Azure Portal、Foundry ポータル、Azure CLI、SDK、IaC、Copilot Studio の操作は行わない。

## 到達目標

- Azure の AI 関連サービスの全体像を理解し、Microsoft Foundry が AI アプリとエージェントを構築、評価、管理するための中心的なプラットフォームであることを説明できる。
- AI エージェントの基本的な仕組みを、モデル、指示、ツール、知識、実行環境、ID、評価、監視の観点で説明できる。
- RAG と Azure AI Search の役割を、モデルにプライベートデータや最新情報を渡すための取得基盤として説明できる。
- Microsoft Foundry を Azure Landing Zone 上で利用する場合に、ネットワーク、認証、データ保護、監視、ガバナンス、リージョン、クォータ、コストの観点で注意すべき点を説明できる。
- Copilot Studio と Microsoft Foundry の使い分けを、利用者、開発スタイル、公開先、制御の細かさ、運用管理の観点で説明できる。
- AI エージェントを使うべきシナリオと、使うまでもない、または別のソリューションを選ぶべきシナリオを判断する入口を持てる。
- 第12回の AI アプリ構築で、どの部分がアプリケーション基盤で、どの部分が AI/エージェントの設計要素なのかを区別して見られる。

## 受講後に説明できること/操作できること

- Microsoft Foundry、Foundry Agent Service、Foundry Models、Azure AI Search、Azure Machine Learning、Copilot Studio の大まかな位置づけを説明できる。
- AI エージェントが、ユーザーの依頼をモデルで解釈し、指示に従い、必要に応じて知識を検索し、ツールを呼び出して応答やアクションを行う流れを説明できる。
- 単純なチャット、RAG を使うチャット、ツールを呼び出す AI エージェント、複数ステップのワークフローの違いを概要レベルで説明できる。
- Copilot Studio はローコードで Microsoft 365 や業務ユーザー向けエージェントを作りやすく、Microsoft Foundry は開発者がモデル、エージェント、ツール、評価、運用を細かく制御しやすい、と説明できる。
- AI エージェント導入時に、権限、データアクセス、プロンプトインジェクション、ツール実行範囲、評価、監視、コストの確認が必要であると説明できる。
- Azure Landing Zone の設計領域のうち、AI ワークロードでは ID、ネットワーク、セキュリティ、ガバナンス、管理の影響が大きいと説明できる。
- 本回は座学のみであり、実際の Foundry プロジェクト作成や Copilot Studio エージェント作成は第12回または別教材で扱うものだと説明できる。

## よくある理解のつまずき

| つまずき | どう補足するか |
| --- | --- |
| Microsoft Foundry をモデルそのものだと思う | Foundry はモデルだけでなく、エージェント、ツール、評価、監視、管理を扱うプラットフォームだと説明する。 |
| Azure OpenAI と Microsoft Foundry の関係が分からない | Azure OpenAI で使っていたモデル利用の考え方が、Foundry のモデルカタログや Foundry リソースの中に整理されてきている、と位置づける。 |
| AI エージェントをチャットボットの言い換えだと思う | エージェントはツール呼び出し、外部データ参照、複数ステップ判断、実行環境、ID を持つ点が重要だと説明する。 |
| RAG とファインチューニングを混同する | プライベートデータや最新情報を参照したい場合はまず RAG、モデルの振る舞いや特定タスク性能を変えたい場合にファインチューニングを検討する、と切り分ける。 |
| AI Search を単なるデータベースだと思う | Azure AI Search は検索/取得のためのサービスであり、業務データの正本を置く DB とは役割が違うと説明する。 |

| AI の監視を通常ログだけで十分だと思う | AI では待ち時間やエラーに加え、品質、接地性、安全性、ツール呼び出し、トークン使用量を追う必要があると説明する。 |
| プレビュー機能を本番前提で考える | プレビュー機能は SLA、利用条件、リージョン、サポート状況を必ず確認する必要があると補足する。 |

## 講師向け補足

- 本回では、Microsoft Foundry と Microsoft Foundry Agent Service を中心に置く。Azure Machine Learning や個別 AI サービスは、名前と利用場面の入口に留める。
- Foundry 周辺は名称、URL、機能、プレビュー状態が変わりやすい。公開前レビューでは、公式ドキュメントの現在の名称、リージョン、モデル可用性、プレビュー表記を確認する。
- 「AI エージェントは万能」という印象を避ける。特にツール実行を伴うエージェントでは、最小権限、実行範囲、監査、人間の確認、失敗時の停止条件を強調する。
- RAG は「検索すれば必ず正しい回答になる」わけではない。データ準備、アクセス制御、検索品質、プロンプト設計、評価が品質に影響することを補足する。
- Copilot Studio と Foundry の比較では、上下関係や単純な優劣にしない。業務ユーザー中心のローコード体験と、開発者中心のカスタム AI アプリ基盤という違いで説明する。
- Azure Landing Zone の説明では、AI だから特別な別枠になるのではなく、既存の ID、ネットワーク、セキュリティ、ガバナンス、管理の上に載ると説明する。
- 第11回に監視サービスが続くため、本回の監視説明は AI 特有のトレース、評価、品質、安全性、トークン、待ち時間に絞り、Azure Monitor の詳細操作には入らない。
- 第12回のサンプルアプリが完成したら、本回のスライド3、4、35に第12回の具体的な構成要素を反映する。
