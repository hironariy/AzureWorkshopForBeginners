DBaaS とは

DBaaS は、データベースサーバーの基盤運用をクラウドサービスに任せ、利用者はデータ、接続、認証、コスト管理に集中する考え方です。

Azure に任せる

基盤運用

物理基盤、マネージド DB 基盤、バックアップ機能、パッチ適用機能などをサービスとして利用します。

利用者が決める

使い方

データモデル、接続元、認証方式、ネットワーク、権限、停止/削除の判断を行います。

ハンズオンの流れ

リソースを作成し、値を記録し、最後に PostgreSQL を停止します。作成操作が多いので、今どこを作っているかを図で確認しながら進めます。

Azure Portal にサインイン

講師が案内したアカウントで Azure Portal に入り、作業対象のサブスクリプションが見えることを確認します。

リソースグループを作成する

第5回と第6回で使う Azure リソースは、受講者ごとの同じリソースグループにまとめます。

リソースグループ作成を確認する

作成したリソースグループの Overview を開き、名前、リージョン、これから作るリソースの配置先を確認します。

VNet を作成する

Container Apps と PostgreSQL の接続を考える土台として、受講者ごとの VNet を作成します。

サブネットを作成する

Container Apps、Private Endpoint、PostgreSQL の用途を分けて、後続手順で参照するサブネット名をそろえます。

ACR を作成する

第6回で Web/API のコンテナイメージを push するため、受講者ごとの Azure Container Registry を作成します。

ACR の Overview を確認する

第6回の GitHub Actions 設定では ACR 名と login server を参照します。画面で確認し、接続情報一覧に記録します。

API Container App と Environment を作成する

まず API 側のプレースホルダー Container App を作成し、この操作の中で Container Apps Environment も用意します。

API Container App の URL を記録する

API の Application URL は、第6回で Web から API を呼び出す設定に使います。Web URL と取り違えないようにします。

Web Container App を作成する

同じ Container Apps Environment に、Web 側のプレースホルダー Container App を作成します。

Web Container App の URL を記録する

Web URL は利用者がアクセスする入口であり、Entra ID アプリ登録の redirect URI と第6回の variables に使います。

PostgreSQL Flexible Server を作成する

Todo データを保存する DB 層として、Azure Database for PostgreSQL Flexible Server を作成します。

PostgreSQL の認証を設定する

元ガイドに合わせ、Microsoft Entra authentication only など講師検証済みの認証設定を選びます。

PostgreSQL のネットワークを設定する

Container Apps から PostgreSQL に接続できるよう、Private access、VNet、Private DNS などの設定を手順に合わせます。

PostgreSQL の作成内容を確認する

作成前に、リージョン、SKU、認証、ネットワークが講師の案内と一致しているか確認します。

PostgreSQL の Overview を確認する

作成後にサーバー名、状態、接続に必要な値を確認し、第6回の接続情報一覧に反映します。

Managed Identity を作成する

DB への権限付与と第6回の設定に使う User-assigned Managed Identity を作成します。

Managed Identity の値を記録する

Client ID や Resource ID は第6回で variables に使います。公開資料ではマスクしつつ、手元メモには正しく記録します。

データベースを作成し権限を付与する

Todo アプリ用の DB を作成し、Managed Identity が DB にアクセスできるように権限を付与します。

Entra ID アプリ登録を作成する

Web サインイン用のアプリ登録を作成し、Web Container App URL を SPA redirect URI として設定します。

アプリ登録の ID を記録する

Application client ID と Tenant ID は第6回の Web サインイン設定で使います。GitHub Actions 用 Service Principal の ID とは別物です。

接続情報一覧に記録する

元ガイドのサマリー項目を見ながら、Resource group、ACR、Web/API URL、PostgreSQL、Identity、Entra ID の値をそろえます。

記録すべき値と隠す値

値を記録することと、公開資料に残すことは別です。第6回で使う値ほど、公開時のマスク対象にもなりやすい点に注意します。

分類例扱い
記録する値Resource group、ACR 名、DB 名、Container Apps Environment第6回用メモに記録
公開時にマスクSubscription ID、Tenant ID、Client ID、FQDN、URLスクリーンショットでは隠す
公開しない値接続文字列、認証情報、Service Principal の secret画面共有にも残さない

作成済みリソースを確認する

リソースグループ内に、VNet、ACR、API/Web Container App、Container Apps Environment、PostgreSQL、Managed Identity がそろっているか確認します。

第5回終了時点のアーキテクチャ

まだ実アプリのコンテナイメージは動いていませんが、デプロイ先、DB、認証、権限、記録すべき値がそろいました。

PostgreSQL を停止する

第6回までリソースは残しますが、DB のコンピュート課金を抑えるため PostgreSQL Flexible Server を Stop します。

停止後の課金注意

Stop は削除ではありません。コンピュート課金を抑える目的で使いますが、ストレージなどの課金が残る可能性はあります。

Running

ハンズオン中

利用可能な状態で、コンピュート課金が発生します。

Stopped

第6回まで

再開可能な状態で止め、コンピュート課金を抑えます。

Deleted

第6回後に判断

不要ならリソースグループや外部資格情報も整理します。

よくある失敗

操作量が多い回なので、名前、権限、ネットワーク、接続情報、停止忘れを短時間で確認できるようにします。

失敗症状確認箇所
名前重複ACR や PostgreSQL 作成に失敗接尾辞、命名制約
権限不足作成やアプリ登録に失敗RBAC、Entra ID 設定
DB 権限漏れ第6回で API から DB 接続に失敗Managed Identity への DB パーミッション
記録漏れ第6回で値が分からない接続情報テンプレート
停止忘れDB が Running のままPostgreSQL Overview

復旧できない場合
