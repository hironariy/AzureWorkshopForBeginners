GitHub Actions が行うこと

GitHub Actions は、手作業で行うビルド、ACR への push、Container Apps の更新を workflow として実行します。

1

コード取得

リポジトリの API/Web コードを使います。

2

ビルド

コンテナイメージを作成します。

3

push

ACR にイメージを登録します。

4

更新

Container Apps の revision を更新します。

デプロイの通信経路

GitHub Actions は Service Principal を使って Azure にログインし、ACR と Container Apps を更新します。PostgreSQL はデプロイ先ではなく、実行時の接続先です。

Secret と Variables

GitHub に登録する値は、秘密情報と設定値に分けます。Secret は値を再表示できない前提で慎重に扱います。

種類例扱い
SecretAZURE_CREDENTIALS値は再表示できない。公開資料に残さない。
Repository variablesRESOURCE_GROUP、ACR_NAME、URL、ID設定値として使う。実環境名や ID は公開時にマスクする。

Service Principal の役割

GitHub Actions は人の代わりに Azure を操作します。その Azure 側の ID として Service Principal を使い、RBAC で操作範囲を決めます。

Identity

Azure 側の実行 ID

workflow が Azure にログインするための ID です。

Scope

操作範囲

原則として第5回のリソースグループをスコープにします。

Role

ロール付与

講師が検証したロールと権限で実行します。

Secret

JSON を登録

取得した JSON は GitHub Secret に入れ、画面共有しません。

第5回の接続情報一覧が、GitHub Actions 設定の入力値になります。Web URL と API URL、ACR 名と login server を取り違えないようにします。
